# Placeholder Audit Report — Quantum Health

**Date:** 2026-11-05
**Scope:** Entire project (source, build pipeline, generated `dist/`, CMS/admin panel, API, SEO/meta, media assets)
**Type:** Read-only audit — **no files were modified.**

---

## 0. How this project works (context for the findings)

- This is a **static HTML/CSS/JS site** generated by `build/gen.js` (no client framework, no runtime DB for the public pages).
- The canonical route registry is `build/structure.js`. It assembles 167 pages from authored modules: `content.js`, `library.js`, `blog.js`, `published-blogs.js`, `extra-pages.js`, `expanded-content.js`, `surgical-subpages.js`, `nonsurgical-subpages-content.js`, `batch4-subpages.js`, `trending-options.js`, `quantum-health.js`, and the research modules (`cochrane.js`, `fda.js`, `nhs.js`, …).
- Real contact data lives in **`build/locations.js`** (single source of truth: `drvikas090909@gmail.com`, `+91 91487 17036`, Hong Kong/Dubai/Bengaluru branches).
- There is a **CMS/admin panel** (static SPA at `/admin`, data via `/api/qh/*`) backed by **Vercel Blob** storage. It already contains a built-in "Placeholder Audit" scanner.
- The **latest active build** is `dist/` (generated 2026-11-05). `dist_old_a4a428/`, `tmpdist/`, `tmpimg/`, `assets-src/` are legacy/temporary copies.

**Overall assessment:** the site is in a very mature state. Educational content, contact data, images, SEO titles/descriptions, forms and navigation are real and complete. The remaining issues are concentrated in (a) the doctor-profile credentials and (b) a handful of legacy/unused config files.

## 2. Findings by category

### 2.1 Confirmed placeholders visible on the live website
- **Dr. Vikas Singh profile** (`/doctors/dr-vikas-singh/`) — four sections are empty placeholders: Professional Memberships, Certifications, Awards & Achievements, and (partly) Social Profiles. (PH-01…PH-04)
- **Dr. Vikas Singh profile** — a stray literal `<|end|>` marker is visible in the "Related Educational Resources" section. (PH-15)
- **Dr. Subramini** (`/meet-doctors/` and `/doctors/dr-subramini/`) — qualifications are shown only as "verification pending". (PH-05)
- **`/doctors/dr-dr-sekhar/`** — double-"dr" slug in the URL. (PH-06)

These are visible on both desktop and mobile (they are standard page sections, not hidden).

### 2.2 Placeholders present in active source code
- `build/quantum-health.js` lines 134, 136, 152–155, 163 (the credential framework, the stray `<|end|>` token, and the four placeholder sections above).
- `build/content.js:27` — stale `og-cover.svg` reference (PH-07).
- `build/content.js:47` and `build/structure.js:509` — empty `medicalDisclaimerShort` (PH-08).

### 2.3 Missing images and media
- **None in the rendered site.** The build runs `verifyImages()` and the image QA pipeline; every referenced image resolves (content-hashed WebP under `dist/assets/responsive/`).
- The **before/after gallery is retired** (`/before-after-gallery/` → 301 to `/understanding-breast-enlargement/`), so the legacy "Consented case / Video to be recorded" pending-frames in `build/images.js` (`pendingFrame`) are **not rendered anywhere**.
- `build/content.js:27` references a non-existent `og-cover.svg` (stale; not rendered). (PH-07)

### 2.4 Broken or dummy links and buttons
- **No broken `href="#"` links found.** The only bare-fragment links are legitimate in-page anchors (`#treatments`, `#pubmed`, `#pmc`, `#choosing-a-surgeon`, `#appointment`, etc.), all of which resolve.
- WhatsApp/tel/email links use real values from `locations.js`.
- PH-04 (missing Facebook/YouTube links) and PH-10 (Resend sender) are the only "dummy link / config" items.

### 2.5 Missing business/contact information
- Opening hours, practitioner availability, and treatment availability are **deliberately not published** (documented in `build/locations.js:15–19` and rendered as honest "confirm directly" notes). This is intentional, not a placeholder.
- `site.contact.address`, `addressNote`, `hours` are empty strings — intentional, backed by per-location notes. (Not a placeholder; flagged for completeness.)
- The canonical domain needs final confirmation (PH-09).

### 2.6 Admin panel and database placeholders
- **No dummy dashboard statistics.** `dashboard.stats` (in `api/_qh/actions.js:549–571`) computes counts from real stored documents (pages, doctors, media, branches, enquiries, drafts, published, missingImages, gallery, components, recent audit log).
- **No sample/seed placeholder records.** `scripts/seed-cms.js` seeds the real authored content from the build (contacts, locations, doctors, review queue).
- The CMS already ships its own placeholder scanner (`placeholders.scan`, `PLACEHOLDER_PATTERNS` at `api/_qh/actions.js:691–707`) plus a static baseline `dist/assets/data/qh-placeholders.json`.
- The review queue (`review-queue.json`, seeded) correctly flags the same medical-credential verification items noted in PH-01…PH-05.
- PH-10: email "from" address falls back to `onboarding@resend.dev` until configured.
- **Limitation:** I could not verify whether the deployed CMS store has actually been seeded (no backend/database access in this environment). The seed script itself contains no placeholder data.

### 2.7 SEO and metadata placeholders
- `<title>` and `<meta name="description">` are real and page-specific for all 167 pages.
- Open Graph uses a real `og-cover.png` (1200×630) with correct width/height/alt on every page.
- Structured data (`schema`) is emitted per page type (WebSite, MedicalWebPage, CollectionPage, ContactPage, AboutPage, FAQPage, Article, Organization/Place).
- PH-07 (stale `.svg`), PH-08 (empty footer disclaimer), and the **absent explicit `<link rel="icon">` favicon** (relies on browser auto-discovery of `/favicon.ico`, which does exist) are the only technical gaps — all **Low**.

### 2.8 Incomplete features or sections
- Dr. Vikas Singh credentials (PH-01…PH-04) — incomplete, waiting on verified records.
- Dr. Subramini qualifications (PH-05) — incomplete, waiting on verification.
- The "Quantum Health STEMCELL RESORT" section on Dr. Sunitha Devaraj's profile is labelled "Proposed or upcoming concept; operational status has not been verified" — an honest, intentional disclosure, not an incomplete feature.

### 2.9 Possible placeholders requiring manual confirmation

- PH-06 (doctor name "Dr. Subramini" vs likely "Dr. Subramani"; also the slug `dr-dr-sekhar`) — confirm correct spelling and slugs with the team.

### 2.10 Unused or legacy-code placeholders (separate from active issues)

## 6. Limitations

- **Browser/rendered-site access:** not available in this environment; findings on visible content are based on the generated `dist/` HTML (which is the exact deploy output) plus the source modules. I did not visually render pages in a browser.
- **Backend/database access:** not available; I could not confirm whether the deployed Vercel Blob CMS store has been seeded, nor inspect live enquiry/media records. (The seed script itself contains no placeholders.)
- **Secrets:** `.env.local` exists and was intentionally **not** read or reported on.
- **Full link/asset QA (`npm run qa`) and Lighthouse were not executed** (requires `npm ci` of esbuild/lighthouse/playwright). Link/asset integrity was assessed by source inspection and the built-in `verifyImages()` + placeholder-scan outputs already present in `dist/`.
